# Maintaining skills

Read this when authoring skills or changing their host entry points.
[AGENTS.md](../AGENTS.md) owns repository-wide invariants and release duties.

## Layout

- `skills/<name>/SKILL.md` — one public entry point per directory; substantial
  conditional instructions live in directly routed `references/` files.
- `scripts/` — dependency-free Node ESM: the manifest sync and the CI checks.
- `.claude-plugin/`, `.agents/`, `.github/plugin/`, `.codex-plugin/`,
  `plugin.json` — per-agent manifests, regenerated by `sync-marketplace.mjs`.
- `templates/` — the `.afk/` starter a consuming project copies.
- `docs/designs/specs/` — design specs.

## Authoring or editing a skill

- Frontmatter needs `name` and `description`. `name` equals the directory name
  and matches `afk` (flagship) or `afk-<slug>` (satellite) — the prefix keeps
  names globally unique so they survive hosts that flatten all skills into one
  namespace, and it removes bare-trigger ambiguity.
- A `description` leads with the namespaced trigger and marks the skill as part
  of the afk pipeline, so its intended selection scope is discoverable. Preserve
  existing natural-language triggers until host behavior validates relocation.
- Cross-reference other skills by relative path (`../afk-kimi-review/SKILL.md`).
- Invoke a bundled `.mjs` helper via the resolved plugin root, never a bare
  relative path. Read [AFK environment](../skills/afk/references/environment.md)
  for the resolution order; a reference directory is not the owning skill root.
- After adding or removing a skill, run `node scripts/sync-marketplace.mjs` so
  the manifests and mirrored version stay consistent.

## Namespacing

Hosts address these skills as `afk-skills:<name>` (Claude) or by their unique
`afk-`prefixed name (flat-namespace hosts). A consuming user's same-named
personal skill overrides a plugin skill — invoke the qualified form, or rename
the local one.
