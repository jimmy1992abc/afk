# GLM-5.3 Review Gate Upgrade

Imported design history. Current decisions are recorded in the
[1.0 integration record](../../port-v1.md).

Issue: [#64](https://github.com/AlvinShenSSW/afk/issues/64)

## Contract

The GLM gate defaults to the pinned `glm-5.3` model through the Z.ai Coding
Plan OpenAI Chat Completion endpoint. It sends the existing bounded snapshot,
requests enabled reasoning at `max` effort, and accepts only a terminal response
whose reported model belongs to the requested lineage.

The Anthropic Messages transport remains available only through
`GLM_REVIEW_PROTOCOL=anthropic`. The protocol is never inferred from the base
URL, and an unknown value is an error before a request starts. The selected
protocol and resolved endpoint appear in `--print-args` diagnostics.

`GLM_REVIEW_MODEL` and `GLM_REVIEW_BASE_URL` override the selected defaults.
An Anthropic override therefore sets both the protocol and, when needed, its
base URL explicitly.

## Decisions

1. `openai` is the default protocol because Z.ai documents an OpenAI-only
   access restriction for some current and former Coding Plan subscribers.
2. `anthropic` remains a closed, explicit compatibility option because Z.ai
   also documents the Anthropic Messages endpoint for GLM-5.3.
3. OpenAI requests carry `thinking.type=enabled` and
   `reasoning_effort=max`. Anthropic requests retain their provider-native
   shape and rely on the model's mandatory reasoning behavior.
4. The snapshot and output budgets stay at 400000 bytes and 8192 tokens. They
   are review-cost bounds, not mirrors of the model limits.
5. The existing shared transport, secret redaction, failure direction, finish
   validation, and model-lineage checks remain the control points.

## Tests

- The default diagnostic names `glm-5.3`, `openai`, and the Coding Plan URL.
- The OpenAI request uses `/chat/completions`, Bearer authentication,
  `max_tokens`, enabled thinking, and max reasoning effort.
- The Anthropic opt-in uses `/v1/messages`, both accepted authentication
  headers, and the existing response parser.
- An invalid protocol fails without sending a request.
- Existing timeout, redaction, malformed response, empty response, truncation,
  identity mismatch, authentication, rate-limit, and 404 behavior remains
  covered.

## Release

The skill and bundled helper change the installed behavior, so the plugin gets
a patch version bump and every generated manifest is synchronized.

## Out of Scope

GLM-5.3-Flash, multimodal inputs, larger review budgets, automatic protocol
detection, silent fallback, and edits to historical design records are excluded.
